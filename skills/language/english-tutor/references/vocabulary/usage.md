# 詞彙與搭配判讀

本文件提供 English Tutor 判斷單字詞義、搭配、語氣、自然度、近義詞與多詞表達時的共同原則。

詞彙分析應以目前語境中的實際用法為中心，而不是將字典中的所有義項一次展開。

## 1. 語境優先

解釋單字時，先根據目前句子的：

- 前後文
- 搭配
- 詞性
- 句法位置
- 語域
- 領域語境

判斷最符合的詞義。

例如：

`get expensive`

中的 `get`

不是「取得」，而是 linking verb，用來表示：

> 變得昂貴

又例如：

`add up fast`

中的 `add up`

在此語境表示：

> 快速累積

不要先列出單字所有字典義，再讓使用者自行猜測哪一義適用。

## 2. 詞性與詞義

同一個字可能因詞性不同而具有不同功能或意思。

例如：

`fast`

可以作：

- adjective
- adverb

因此詞義判讀必須同時考慮詞性與句法功能。

例如：

`a fast server`

中的 `fast` 是 adjective。

而：

`Costs add up fast.`

中的 `fast` 是 adverb。

不要只根據單字最常見的詞性判斷目前用法。

## 3. Collocation

自然英文不只取決於單字意思，也取決於單字通常如何搭配。

例如：

`make a decision`

通常比：

`do a decision`

自然。

因此分析詞彙時，必要時確認：

- verb + noun
- adjective + noun
- adverb + adjective
- verb + adverb
- preposition choice
- fixed or semi-fixed combination

搭配詞往往比單一詞義更能決定實際意思。

不要因為兩個字中文翻譯相近，就假設它們能出現在相同 collocation 中。

## 4. 自然度判讀

判斷英文表達時，應區分至少以下維度：

### 文法成立

句法結構符合英文規則。

### 自然／常見

母語使用中屬於正常且常見的表達。

### 語域限定

可能只常見於：

- formal
- informal
- conversational
- academic
- business
- technical
- literary

### 少見但可接受

文法成立，但在目前語境較少使用。

### 不自然

即使能理解，實際英文通常不這樣表達。

### 文法不成立

結構本身不符合目前分析下的英文句法要求。

不要把：

> 少見

直接等同於：

> 錯誤

也不要把：

> 文法成立

直接等同於：

> 自然。

## 5. 近義詞

近義詞通常只共享部分語意，不代表可以完全互換。

比較近義詞時，優先確認：

- 核心意思
- 詞性
- collocation
- register
- emphasis
- connotation
- syntactic position
- interchangeability

例如：

`fast`

與：

`quickly`

都可以表示快速，但搭配與自然度不一定完全相同。

因此不要只提供：

`fast = quickly`

而應說明在目前語境是否可以替換，以及替換後是否自然。

## 6. 易混淆詞

形式相似不代表意思相同。

例如：

`hard`

與：

`hardly`

意思明顯不同：

`work hard`

→ 努力工作

`hardly work`

→ 幾乎不工作

又例如：

`late`

與：

`lately`

也不能視為單純 adjective / adverb 形式變化：

`late`

→ 遲、晚

`lately`

→ 最近

不要假設加入 `-ly` 後只改變詞性而保持原義。

## 7. 多義詞

同一個字可能具有多個相關或不相關的意思。

分析時：

1. 先選擇目前語境最合理的意思。
2. 必要時說明它與基本義的關係。
3. 只有當其他義項容易造成誤解時，才補充比較。

不要為了完整而列出所有 dictionary senses。

## 8. Phrasal Verb 與多詞表達

phrasal verb、idiom、fixed expression 與 collocation 應優先以整體分析。

例如：

`take the application down`

在 Software / Operations 語境通常表示：

> 讓應用程式停止服務／停機

不能只把：

`take`

翻成「拿」，

再把：

`down`

翻成「向下」，

然後拼湊意思。

逐字翻譯可以作為輔助，但不能取代整體語境義。

若主要學習重點已經是整個多詞結構，應交由 `phrase-analysis.md` 深入分析。

## 9. Register 與語氣

詞彙選擇可能受到語域影響。

必要時區分：

- formal
- neutral
- informal
- conversational
- academic
- professional
- technical

同一個基本意思在不同 register 中可能使用不同詞彙。

只有當 register 會影響目前問題時才補充，不要每個單字都機械式標示正式度。

## 10. 領域語意

專業領域可能賦予一般英文單字特定意思。

例如：

`instance`

在一般英文可以表示：

> 例子／實例

但在 software / cloud context 中可能表示：

> 執行中的服務實例、VM instance 或 application instance

應依上下文保留正確的領域意思。

若領域知識本身需要額外說明，可參考 `domains/technical-context.md`。

不要因為詞彙具有專業意思，就把整個英文問題展開成領域教學。

## 11. 替代詞判讀

提出替代字前，先確認替換後是否改變：

- 意思
- 詞性
- 搭配
- 語序
- 語氣
- register
- naturalness

替代字應分成：

- 可直接替換
- 特定語境可替換
- 意思接近但不可直接替換

不要因為 dictionary synonym 相同，就宣稱兩個字可以完全互換。

## 12. 判讀限制

- 語境優先於孤立字義。
- collocation 是詞彙用法的重要證據。
- 詞性必須依目前句法位置與功能判斷。
- 中文翻譯相同不代表英文用法相同。
- synonym 不代表 interchangeable。
- grammatical、natural、common、formal 與 semantic equivalence 是不同判斷維度。
- 少見但合法的表達不可直接判定為錯誤。
- 不要一次列出與目前問題無關的所有字典義。
- 不要一次展開大量近義詞。
- multi-word expression 應先分析整體，再視需要分析個別單字。
- 領域詞義應依上下文判斷，不要預設所有英文都是一般義或技術義。
- 分析深度以解決使用者目前問題為準。
