# 英文知識筆記版型

適用於使用者要求將英文學習內容整理成可長期保存、查閱與複習的 Knowledge Note，例如：

- 幫我整理成筆記
- 產生知識庫文件
- 整理成 Markdown
- 幫我做成英文學習筆記
- 把剛才的內容整理成知識卡
- 建立句型筆記
- 整理到我的 English Knowledge Base

Knowledge Note 的目的不是重複聊天回答，而是將已確認的英文知識重新組織成：

- 可獨立閱讀
- 可快速查找
- 可長期維護
- 可交叉比較
- 可複習
- 可遷移到其他英文情境

的知識文件。

## 1. Knowledge Note 不是新的文法分析系統

Knowledge Note 是 presentation / persistence format。

建立筆記前，先判斷知識主體屬於：

- word
- phrase
- pattern
- grammar
- comparison

再使用對應分析原則整理。

不得因為輸出 Knowledge Note，就重新建立另一套與既有 templates / references 不一致的 grammar model。

Knowledge Note 中的：

- 詞類
- syntactic form
- grammatical function
- semantic function
- grammar terminology

必須與 English Tutor 其他分析保持一致。

## 2. 筆記來源

優先使用目前對話中已經確認的分析結果。

如果 Knowledge Note 是從使用者提供的：

- 原句
- 文件
- 筆記
- 教材
- reference material

整理而來，應保留其原始 terminology、例句與核心 framing。

不要為了讓筆記看起來完整，而自行加入來源沒有支持的結論。

若使用者要求：

- 補充
- 擴充
- 驗證
- 研究
- 比較

才加入額外知識，並保持與原始內容的邊界清楚。

## 3. 先判斷筆記類型

建立 Knowledge Note 前，先選擇主要類型。

### Word Note

適用於：

- 單字
- 詞性
- contextual meaning
- usage
- collocation
- confusing words

### Phrase Note

適用於：

- phrase
- idiom
- phrasal verb
- collocation
- fixed expression
- multi-word expression

### Pattern Note

適用於：

- reusable sentence pattern
- verb complementation
- argument structure
- 可遷移的句法公式

### Grammar Note

適用於：

- grammar concept
- grammatical function
- syntactic distinction
- clause / phrase concept
- verb form
- modifier
- complement

### Comparison Note

適用於：

- word vs word
- phrase vs phrase
- pattern vs pattern
- grammar distinction
- confusing expressions

若一份內容同時涉及多種類型，以主要學習目標決定文件類型，不要建立混合型巨大筆記。

# Word Note

Word Note 依內容需要選用以下區段。

不要為了湊齊模板而全部輸出。

## 核心意思

先說明此單字在主要語境中的核心意思。

若有多義，只保留：

- 高頻義
- 與目前學習內容直接相關的義
- 容易造成混淆的義

不要建立完整 dictionary dump。

## 詞性

列出與目前筆記相關的詞性。

例如：

`fast`

- adjective
- adverb

必要時說明同一形式如何具有不同功能。

## 語境中的意思

若詞義會依 context 改變，提供少量代表性語境。

例如：

`instance`

在不同 technical context 可能具有不同 referent。

不要在 context 不足時武斷指定唯一技術義。

## 常見搭配

只保留真正具有學習價值的 collocations。

例如：

`highly effective`

`work hard`

`respond fast`

不要建立大量無關搭配清單。

## 位置與語序

只有當位置會影響：

- grammatical function
- naturalness
- meaning
- emphasis

時加入。

## 易混淆字

只比較真正容易混淆的表達。

例如：

`hard` vs `hardly`

`late` vs `lately`

不要為了增加內容列出大量 synonyms。

## 例句

使用少量自然例句。

例句應：

- 展示不同功能
- 展示典型搭配
- 隔離真正差異

不要只替換名詞製造大量重複句。

## 一句話記憶

只有存在安全且可遷移的規則時提供。

---

# Phrase Note

Phrase Note 可選用以下區段。

## 核心意思

先說明整個 phrase 的自然意思。

非字面表達必須先說整體義，再視需要解釋組成。

例如：

`take the service down`

在 Software / Operations context 通常表示：

> 讓服務停止運作。

不要先逐字翻譯再拼湊意思。

## 結構拆解

必要時標示：

- head
- object
- particle
- preposition
- complement

例如：

`take + O + down`

## 原始例句

保留最能代表此 phrase 的原始例句。

## 在句中的功能

說明 phrase：

- 修飾什麼
- 補足什麼
- 描述什麼
- 與哪個成分形成關係

## 常見用法

只列具有代表性的語意或搭配。

## 易混淆表達

比較真正容易混淆的 phrase。

## 語境與語域

只有當：

- technical context
- formal / informal
- spoken / written
- domain-specific usage

會影響理解時加入。

## 記憶方式

保留最值得遷移的整體概念。

---

# Pattern Note

Pattern Note 是句型知識庫的主要格式。

建議優先使用以下結構。

## 1. 核心意思

用一小段話說明句型表達的核心關係。

例如：

`leave + O + with + NP`

核心概念可以表達為：

> 某件事情造成一個結果，使 O 最後留下、具有或面臨 `with + NP` 所描述的情況。

不要只給中文公式翻譯。

## 2. 句型結構

列出可重用公式。

例如：

`leave + O + with + NP`

必要時使用表格：

| 成分 | 分析 | 功能 |
| --- | --- | --- |
| `leave` | V | 主要動詞 |
| `O` | Object | 受到結果影響的人或事物 |
| `with + NP` | PP | 描述 O 最後具有或面臨的結果 |

句型表格必須區分：

- syntactic form
- grammatical function
- semantic function

不要把 NP / PP 與 O / C / OC 當成同一層級。

## 3. 原始例句

保留最重要的來源例句。

例如：

> Sending a big search query over HTTP left me with two bad choices.

提供自然翻譯。

不要為了筆記格式任意改寫原句。

## 4. 例句拆解

只有當拆解能幫助理解句型時加入。

例如：

`Sending a big search query over HTTP`
→ S

`left`
→ V

`me`
→ O

`with two bad choices`
→ PP

不要對每個單字進行不必要分析。

## 5. 為什麼這樣用

說明：

- 動詞在此處的意思
- argument relationship
- attachment
- semantic result
- 為什麼不能逐字理解

這一節應回答：

> 為什麼英文會用這個結構表達這個意思？

而不只是重新翻譯一次。

## 6. 常見語意／用法

依句型實際用途分類。

例如：

- 剩下某物
- 面臨選擇
- 留下問題
- 形成某種結果

每種類型只需要少量代表例句。

## 7. 易混淆結構

比較表面相似但 grammatical relation 不同的結構。

例如：

`leave + O + with + NP`

vs.

`leave + O + OC`

比較時說明：

- 哪個成分改變
- grammatical function 如何改變
- meaning 如何改變

不要只列：

> A 對，B 錯。

## 8. 常見搭配

只保留具有實際複習價值的搭配。

例如：

`leave someone with no choice`

`leave someone with two options`

`leave someone with a problem`

`leave someone with the impression that ...`

不要建立過長 phrase list。

## 9. 相近表達

比較意思接近但句法或語氣不同的表達。

例如：

`leave O with X`

vs.

`give O X`

應說明：

- 共同點
- 差異
- 是否可互換
- focus 如何不同

## 10. 常見錯誤

只有存在實際學習風險時加入。

例如：

- 把 PP 自動標成 OC
- 把 semantic result 當 grammatical function
- 逐字翻譯 phrasal meaning

沒有明顯錯誤風險時可以省略。

## 11. 記憶公式

將句型壓縮成可遷移規則。

例如：

`leave + O + with + NP`

↓

`某件事發生`

↓

`O 最後留下／面臨 X`

記憶公式必須：

- 簡短
- 可遷移
- 不扭曲 grammar

## 12. 一句話記憶

用一句繁體中文保留最值得記住的概念。

例如：

> `leave + O + with + NP` 的重點不是「離開」，而是某件事造成結果，使 O 最後留下或面臨 X。

# Grammar Note

Grammar Note 用於建立概念型知識文件。

## 核心概念

先回答：

> 這個 grammar concept 是什麼？

## 判斷方法

提供實際判斷流程。

例如 C vs OC：

1. 找主要動詞。
2. 找被描述的成分。
3. 描述 S → C。
4. 描述 O → OC。

判斷流程應比抽象定義更優先。

## 結構

列出相關句型或 form。

## 典型例句

提供少量 canonical examples。

## Minimal Contrast

優先使用 minimal pairs。

例如：

`The service became unavailable.`

vs.

`The update made the service unavailable.`

用來隔離：

`C`

與：

`OC`

的差異。

## 常見錯誤

列出真正容易誤判的情況。

## 邊界情況

只有存在：

- grammar-framework difference
- context dependency
- ambiguous attachment

時加入。

不要為了顯得完整而製造理論爭議。

## 判斷公式

最後提供簡潔 decision rule。

## 一句話記憶

只在可以安全泛化時提供。

---

# Comparison Note

Comparison Note 應以差異為中心，不是分別寫兩篇百科。

## 核心差異

先直接回答：

> A 和 B 最重要的差別是什麼？

## 結構對照

必要時使用表格：

| 項目 | A | B |
| --- | --- | --- |
| 詞性／結構 | ... | ... |
| 核心意思 | ... | ... |
| 使用情境 | ... | ... |
| 是否可互換 | ... | ... |

## Minimal Pairs

盡量使用相同詞彙，只改真正需要比較的部分。

## 為什麼意思改變

說明：

- grammatical function
- syntactic form
- collocation
- semantic scope
- register

如何造成差異。

## 是否可以互換

明確分類：

- 可以
- 特定 context 可以
- 意思接近但不完全相同
- grammatical but different meaning
- 不可互換

## 常見誤解

只有存在實際風險時加入。

## 一句話記憶

用一句話收斂真正差異。

---

# 文件命名

Knowledge Note 的檔名應：

- 簡短
- 可搜尋
- 能看出主要知識點
- 避免只使用完整原句作檔名

Pattern Note 優先使用抽象結構。

例如：

`leave O with NP.md`

優於：

`Sending a big search query over HTTP left me with two bad choices.md`

`keep O V-ing.md`

優於：

`keep multiple instances running.md`

若使用者已有自己的命名慣例，優先遵循既有 Knowledge Base convention。

不要為了統一格式任意重新命名既有文件。

---

# 標題命名

文件 H1 應直接表達知識主題。

例如：

`# leave + O + with + NP`

`# keep + O + V-ing`

`# without + V-ing`

`# fast vs quickly`

不要使用：

`# 英文筆記 01`

`# 今天學到的英文`

等缺乏搜尋價值的標題。

---

# Markdown 結構

Knowledge Note 應：

- 只有一個 H1
- 主要區段使用 H2
- 次分類使用 H3
- 公式與英文片段使用 inline code
- 完整例句可使用 blockquote 或獨立行
- 比較多個成分時才使用 table
- 不使用過深 heading hierarchy
- 不為每一句話建立 heading

避免：

- 大量空白 section
- 重複標題
- 過度裝飾
- 大量 emoji
- 為單一資訊建立表格
- 把整篇文件做成 checklist

---

# 資訊密度

Knowledge Note 應比聊天回答更穩定，但不代表更長。

優先保留：

1. 核心規則
2. 結構
3. 代表例句
4. 易混淆點
5. 可遷移規則

降低：

- 對話式開場
- 重複翻譯
- 過度鼓勵
- 大量近義詞
- 百科式背景
- 不影響理解的 technical explanation

每一節都應回答一個不同問題。

如果兩節內容高度重複，應合併或刪除其中一節。

---

# 原始例句與新增例句

應區分：

### 原始例句

使用者實際提供或目前學習來源中的句子。

### 補充例句

為了展示規則而新增的句子。

不要把新增例句冒充原始來源。

如果筆記是從特定文件整理而來，不要自行改寫來源例句後仍標示為原始例句。

---

# 技術英文

Technical English 只是 Knowledge Note 的可能 context。

技術句型筆記可以保留：

- application
- service
- instance
- request
- response
- Deployment
- Pod
- API
- HTTP

等實際 terminology。

不要為了「一般化英文」而破壞 technical meaning。

同時也不要因為例句涉及 Kubernetes、HTTP 或 Security，就把 Knowledge Note 擴張成技術文件。

只補充理解英文所需要的最小 domain context。

---

# Learning Focus 與 Knowledge Note

Learning Focus 與 Knowledge Note 的責任不同。

Learning Focus：

> 從單次回答中選出 1～2 個最值得記住的規則。

Knowledge Note：

> 將一個知識主題整理成可以長期查閱的文件。

建立 Knowledge Note 時，可以使用 Learning Focus 幫助決定：

- 記憶公式
- 一句話記憶
- 哪些內容最值得保留

但不要把 Learning Focus 直接複製成整份 Knowledge Note。

---

# Correction 與 Knowledge Note

若 Knowledge Note 來自 Correction：

不要把使用者錯誤句本身當成主要 canonical example。

可以建立：

### 常見錯誤

`without restart`

→ 不符合目前 intended structure

### 正確結構

`without restarting`

→ `without + V-ing`

Knowledge Note 應保存：

> 可遷移規則

而不是保存：

> 使用者曾經犯過什麼錯。

除非使用者明確希望建立個人錯題筆記。

---

# 去重原則

## Knowledge identity 與核心結構

Pattern Note 的 knowledge identity 應優先保留必要成分與可重用的 grammatical relationship。

原始例句中的 optional modifier 不會自動成為 pattern identity 的必要部分。若移除該 modifier 後，核心 grammatical structure 與 relationship 仍成立，通常不應將它納入主要 identity。

有學習價值的 optional modifier 仍可保留在原始例句分析、usage extension、comparison 或 modifier analysis 中。

建立 Knowledge Note 前，若已知 Knowledge Base 中存在相同主題，優先：

- 更新既有筆記
- 合併新知識
- 補充新例句
- 補充新的 comparison / warning

而不是建立第二份幾乎相同的文件。

例如已存在：

`keep O V-ing.md`

則：

`keep multiple instances running`

通常應整理進既有句型筆記，而不是建立另一份重複文件。

若無法確認 Knowledge Base 是否已有相同主題，不要假裝已完成去重。
