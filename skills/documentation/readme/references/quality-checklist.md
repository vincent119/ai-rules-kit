# README 品質稽核

先完整閱讀 README，再依下列六類各自評分。分數用於排序改善工作，不用來強迫每個專案採相同篇幅。

| 類別 | 上限 | 核心問題 |
|---|---:|---|
| 第一印象 | 20 | 讀者是否立即理解價值與對象？ |
| 開始使用 | 20 | 能否從零到可觀察結果？ |
| 使用與範例 | 20 | 範例是否真實、漸進、可複製？ |
| 結構與掃讀 | 15 | 關鍵資訊是否易找且篇幅適當？ |
| 正確性與維護 | 15 | API、命令、版本、連結與其他文件是否一致？ |
| 完整性 | 10 | 授權、貢獻、支援與限制是否在適用時清楚？ |

每個類別以 0 至 5 評估其中項目：0 至 1 表示缺失或誤導，2 至 3 表示可用但有缺口，4 至 5 表示可直接讓目標讀者成功。至少檢查：標題與開場、安裝完整性、quick start、前置條件、版本與平台、真實範例、複製可行性、預期輸出、heading 結構、篇幅、格式、API／CLI 漂移、連結、跨文件一致性、授權、貢獻、支援與限制。

## Audit 輸出

輸出總分、六類分數、三項優勢及依影響排序的三項改善。每個改善都要指出觀察到的內容、來源證據與可採取的修正；正確性問題優先於措辭與版面。
