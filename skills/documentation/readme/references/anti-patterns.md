# 反模式

## 內容與範圍

- **技術清單取代價值主張**：開頭只列框架或內部元件。改為說明讀者用它能完成什麼。
- **README 當文件站**：列出所有 API、內部模組與歷史決策。改為保留入門與常見路徑，深入內容連到專門文件。
- **無條件套樣板**：為簡單工具塞入架構圖、二十個 badge、貢獻流程。每一節都需能回答讀者的問題。
- **混合 quick start 與完整安裝**：讓初次讀者在多種平台選項中迷路。快速開始只保留最快成功路徑。

## 正確性與可維護性

- **憑記憶寫命令、旗標或 API**：必須由 manifest、parser、公開 export 或 schema 證實。
- **把搜尋命中視為公開契約**：確認的是定義與公開入口，不是任意字串出現。
- **不顯示成功訊號**：讀者無法判定範例是否運作。必要時給預期輸出、畫面或明確結果。
- **未驗證 badge、連結與版本**：連結要能到達，版本與相容性需由 release、manifest 或 CI 證實。

## 表達與可讀性

- **行銷形容詞沒有證據**：例如「極快」「企業級」。改為可驗證能力、限制或量測資料。
- **片段無法複製**：補足 import、前置條件與標示的 placeholder；不要要求讀者猜隱藏狀態。
- **過度註解或密集長文**：僅說明非直覺決策，將可掃讀資訊改為標題、清單與表格。
- **複製 LICENSE、CONTRIBUTING、CHANGELOG**：若已有專門檔案，以一行連結取代重複內容。
