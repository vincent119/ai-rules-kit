# 文件結構與資訊順序

使用「讀者能否安全完成下一步」決定順序，而不是把所有段落一律排進去。共通開頭先說目的、讀者、範圍、非目標與前置條件；再提供主要模型或流程；最後交代驗證、限制、風險與延伸閱讀。

## 架構文件

建議順序：背景與問題、系統邊界、元件責任、資料／控制流圖、關鍵介面與資料、非功能取捨、失敗模式與觀測、限制、相關 ADR。圖中每個元件都要有責任；不確定的連線要標為假設或待確認。

## 操作手冊

建議順序：目的與適用時機、影響與權限、前置檢查、程序、每步成功訊號、驗證、rollback、故障排除、升級與紀錄。指令區塊前要指出執行環境與變數；不要要求使用者在不知道影響的情況下刪除、覆蓋或重啟資源。

## 教學與概念文件

教學用「目標、前提、步驟、結果、延伸練習」；概念文件用「問題、術語、心智模型、例子、限制、相關概念」。一段只引入一個新概念，程式碼或圖表後緊接讀者需要理解的解釋。

## ADR

建議順序：標題、狀態、日期、context、決策、替代方案、後果、實作與驗證、相關 ADR。結論必須能從 context 與取捨追溯，不以結果反向合理化決策。
