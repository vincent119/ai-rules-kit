# 文件類型與選擇

先問讀者要理解、決定或完成什麼，不要只依檔名選格式。一份文件可連結其他類型，但應有一個主要目的。

## 架構文件

適用於新成員理解系統邊界、元件責任、資料流與操作風險。先說明問題與範圍，再以可維護的圖描述主要流程；圖後要解釋資料如何流動、失敗如何處理及哪些元件不在範圍。不要做逐檔案導覽或把推測當架構事實。

## 操作手冊

適用於部署、維護、升級、復原與例行操作。每個程序都需要適用條件、權限、前置檢查、具順序的指令、成功訊號、停止條件、rollback 與升級路徑。操作步驟必須與實際工具、設定及環境一致；不要將危險指令寫成沒有防護的萬用流程。

## 教學

適用於讓特定讀者學會一項能力。設定讀者前提與最終可觀察成果，將內容切成循序遞進的小步驟；每一步要說明目的、操作、預期結果與常見失敗。教學不是 API 全表，也不是僅列出命令。

## ADR

適用於保留已作決策的脈絡。ADR 記錄當時的 context、選擇、考慮過的替代方案、後果與狀態；它不應被事後改寫成「唯一正確答案」。決策已被取代時新增 superseding ADR 並互相連結。

## 概念說明

適用於建立共同心智模型，例如佈署模式、領域術語或安全邊界。從問題、術語、核心模型、適用情境與非適用情境逐步說明。讀者應能用自己的話解釋概念，而不是只記住定義。
