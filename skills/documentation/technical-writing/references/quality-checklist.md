# 技術文件品質稽核

先確認文件的讀者與預期成果，再檢查以下面向。技術正確性與安全操作優先於措辭、格式與篇幅。

| 面向 | 必要檢查 |
|---|---|
| 目的與邊界 | 讀者、目的、範圍、非目標、前置條件是否明確。 |
| 正確性 | 命令、設定、介面、圖與風險是否有目前來源佐證。 |
| 可執行性 | 每一步有執行位置、成功訊號、停止條件與失敗處理。 |
| 結構 | heading 可掃讀、段落順序支援讀者決策，長文件有導覽。 |
| 可維護性 | 有 owner 或更新條件、連到權威來源，避免複製會漂移的細節。 |
| 安全性 | 權限、不可逆操作、敏感資料與 rollback 被明確處理。 |

## Audit 輸出

先列出已驗證事實與待確認項目，再按影響排序列出三至五個改善。每個改善包含：問題、受影響讀者或風險、來源證據、建議修正與驗證方式。不要只說「內容不足」或「請更清楚」。
